II

The split

Reflexes on the Pixhawk. Thinking on the Pi. One cable.

ArduRover already closes the turn-rate and speed loops, mixes skid steering, runs EKF3 and owns every failsafe. Rewriting that on Linux would move a loop that must not stall onto a machine that sometimes does. The Pi sends intent. One node is allowed to speak MAVLink, as sysid 245. A mission is a client of /rupsha/move and cannot, by construction, write a motor command.

III

A marker leg

The longest loop the stack has closed

Headless Gazebo, the whole stack: manager, vision, localization, executive, against ArduRover SITL. The leg is a GNSS point 6 m short of post 3, then a search, then an approach, then a verify that refuses to succeed because the rover merely stopped.

NAVIGATING
    → SEARCH_PATTERN          three frames, or drive back to a held estimate
    → APPROACHING_MARKER      pixels inside 4.5 m, else a point short of the tag
    → VERIFYING_MARKER        the tag still in view, range ≤ 2.5 m, most of 1.5 s
    → done

a loss under the retry cap goes back a state
stuck reverses, then tries the search again

Each fix uses the rover pose at the image's capture time, interpolated across 3 s, plus the camera's 0.33 m offset on the Gazebo model. Ten fixes, weighted by one over range squared, held 30 s. A retry that already has three of them drives back. It does not spiral the estimate away.

IV

The record

Four states, and they are not blended

FIELD is outdoors, on the rover. There is no row in that state. BENCH is the real board on a desk, or the real code closing a loop against SITL or Gazebo. BUILT is code and tests that have not closed a loop. BLOCKED says what it is waiting on.
